# API вкладки «Аналитика: движение жилого фонда»

Спецификация методов для мобильного приложения АСУ «Мои Дома» Light.
Логика расчётов повторяет ТЗ дашборда «Движение жилого фонда» (MasterCatalog, dcdb16).

## Принципы

* Один основной метод отдаёт всё, что нужно для первого экрана (KPI, список регионов,
  ряд для графика). Два вспомогательных — детализация по региону и точки для карты.
  Так экран рисуется за один запрос, а детализация грузится по тапу.
* Период передаётся пресетом (`period`) либо явными датами (`from`/`to`).
  Значение по умолчанию — `month`.
* Пользовательский скоуп применяется автоматически: обычный пользователь получает
  только свои регионы/УК (`users.regions`, `users.uks`), `superadmin` — все.
  Доп. фильтр `region_id` / `uk_id` сужает выборку внутри скоупа.
* Ответы не кэшируются на сервере (как и остальные методы Light). На клиенте
  допустим кэш на время сессии по ключу «период + фильтр».
* Все площади — в м² с двумя знаками; даты — `YYYY-MM-DD`; суммы считаются
  **на последний день периода** (`as_of`).

## Пресеты периода

| `period`    | from                     | to                           | Шаг графика по умолчанию |
|-------------|--------------------------|------------------------------|--------------------------|
| `month`     | 1-е число текущего месяца | последний день текущего месяца | `week`                 |
| `quarter`   | 1-е число текущего квартала | последний день текущего квартала | `month`             |
| `year`      | 1 января текущего года   | 31 декабря текущего года       | `month`                |
| `half_year`, `ytd` | оставлены для совместимости | —                    | `month`                |
| `custom`    | `from` (обязателен)      | `to` (обязателен)            | подбирается: ≤ 62 дн. → `week`, ≤ 18 мес. → `month`, иначе `quarter` |

`to` в будущем допускается (конец текущего месяца): события с датой позже «сегодня» просто не попадут.

## Правила расчёта (из ТЗ)

* Площадь региона = Σ `BUILDSPACE.LIVINGAREA` + Σ `BUILDSPACE.NONLIVINGAREA` при `ACTUAL = 1`.
* Кол-во домов = `count(BUILDTABLE.ID)` домов, находящихся в обслуживании на `as_of`.
* Регион = `ADDRESSSTATE.NAME` через `BUILDTABLE → ADDRESSTABLE → ADDRESSTOWN → ADDRESSSTATE`.
* Движение — `BUILDMANAGEMENT` (`IsCorrect = 1`) с `ENTRYDATE` в `[from, to]`:
  * **ушедший** дом — переход к УК с `UKPROP.UKSOBSTV = 0`;
  * **пришедший** дом — переход к УК с `UKPROP.UKSOBSTV = 1`;
  * переход между двумя УК холдинга (обе `UKSOBSTV = 1`) **исключается**.
* Дельта площади/домов = пришло − ушло; знак определяет цвет (зелёный ≥ 0, красный < 0).

## 1. `GET /api/analytics/housing-movement`

Сводка для главного экрана вкладки (варианты A/B/C макета).

### Параметры запроса

| Параметр     | Тип      | Обяз. | Описание |
|--------------|----------|-------|----------|
| `period`     | enum     | нет   | `month` (по умолчанию) · `half_year` · `ytd` · `year` · `custom` |
| `from`, `to` | date     | при `custom` | Границы периода включительно |
| `step`       | enum     | нет   | Шаг ряда `series`: `week` · `month` · `quarter`. По умолчанию — из таблицы пресетов |
| `region_id`  | uuid     | нет   | Ограничить одним регионом (тогда `regions[]` содержит один элемент, а `uks[]` — УК этого региона) |
| `uk_id`      | int      | нет   | Ограничить одной УК |
| `group_by`   | enum     | нет   | `region` (по умолчанию) · `uk` — чем заполнять блок `groups[]` |
| `include`    | csv      | нет   | Доп. блоки: `series` (ряд для графика), `uks` (топ УК). По умолчанию `series` |

Назначение блоков на макетах:

| Блок ответа       | Вариант A                     | Вариант B                      | Вариант C                       |
|-------------------|-------------------------------|--------------------------------|---------------------------------|
| `summary`         | 4 KPI-плитки                  | сводная карточка + полоса баланса | итог за период + 2 плитки    |

### Ошибки

* `422` — `custom` без `from`/`to`, `from > to`, период длиннее 36 месяцев, неизвестный `step`.
* `403` — `region_id`/`uk_id` вне скоупа пользователя.
* `502` — источник данных (MasterCatalog) недоступен; тело `{ "message": "Источник данных недоступен" }`.

## 2. `GET /api/analytics/housing-movement/houses`

Детализация: список ушедших/пришедших домов (экран «Детализация региона», режимы карты «Ушедшие/Пришедшие дома»).

### Параметры

| Параметр     | Тип   | Обяз. | Описание |
|--------------|-------|-------|----------|
| `period`, `from`, `to` | — | как в методе 1 | |
| `region_id`  | uuid  | нет   | Регион |
| `uk_id`      | int   | нет   | УК (прежняя УК для ушедших, новая — для пришедших) |
| `direction`  | enum  | нет   | `out` · `in` · `all` (по умолчанию `all`) |
| `sort`       | enum  | нет   | `date_desc` (по умолчанию) · `area_desc` · `address` |
| `page`, `per_page` | int | нет | Постранично, `per_page` ≤ 100, по умолчанию 50 |

### Ответ `200`

## 3. `GET /api/analytics/housing-movement/map`

Точки для карты (кнопки «Все дома / Ушедшие / Пришедшие»). Отдельный метод, чтобы
пан/зум карты и смена режима не перерисовывали таблицы и график (требование ТЗ, п. 4).

### Параметры

`period`/`from`/`to`, `region_id`, `uk_id`, `mode` = `all` · `out` · `in` (по умолчанию `all`),
`bbox` = `minLon,minLat,maxLon,maxLat` (опционально — отдаёт только точки в видимой области).

### Ответ `200`

```json
{
  "mode": "out",
  "count": 21,
  "points": [
    { "build_id": "0200263", "lat": 56.0106, "lon": 92.8526, "direction": "out", "area_total": 8420.00 }
  ]
}
```

Режим `all` отдаёт все обслуживаемые дома скоупа с `direction: null` — для больших регионов
клиенту стоит передавать `bbox` и кластеризовать точки. Полная карточка точки берётся
методом 2 или существующим `GET /api/houses/card`.

## Реализация на бэкенде (Laravel)

* `routes/api.php` — группа `auth:sanctum` + `active`:
  `Route::get('analytics/housing-movement', [AnalyticsController::class, 'summary'])`,
  `…/houses` → `houses`, `…/map` → `map`.
* `App\Support\Period` — разбор `period/from/to/step` в `[from, to, as_of, step]`, валидация пресетов.
* `App\Services\HousingMovementService` — SQL к MasterCatalog (отдельное подключение `mastercatalog`
  в `config/database.php`, MS SQL / `sqlsrv`), три запроса:
  1. остатки на `as_of` (площадь, кол-во домов) по регионам/УК;
  2. события `BUILDMANAGEMENT` за период с `UKSOBSTV` прежней и новой УК → `in/out`;
  3. агрегация событий по корзинам `step` для `series`.
* `AccessScope` — применяется к результату так же, как в `HouseController`
  (фильтрация по `users.regions` / `users.uks`).
* Пагинация и сортировка метода 2 — на стороне SQL.

## Клиент (React Native)

* Новая вкладка `AnalyticsTab` в `RootNavigator`: стек `Analytics → RegionDetail → HouseCard`
  (`HouseCard` — существующий экран, открывается по `build_id` + `card_mark`).
* Хук `useHousingMovement({ period, from, to, step, regionId, groupBy })` → один запрос метода 1;
  `useMovementHouses(...)` — метод 2 с бесконечной прокруткой.
* Графики — `react-native-svg` (уже в проекте): столбики `area_in` вверх / `area_out` вниз,
  полилиния по `area_delta`; шкала — по `max(|area_in|, |area_out|)` ответа.
* Шторка периода хранит выбор в AsyncStorage (`analytics.period`), по умолчанию `month`.

## Реализация (ноябрь 2026)

Кондуктор отдаёт метод `analyticsHousingMoving`; бэкенд Light проксирует его как
`GET /api/analytics/housing-movement` (контроллер `App\Http\Controllers\AnalyticsController`).

Отличия фактического ответа кондуктора от спецификации выше — что учтено в приложении:

* `summary.area_in/area_out/houses_in/houses_out` приходят нулевыми. Бэкенд пересчитывает
  весь блок `summary` суммированием по `groups` — заодно это ограничивает итоги
  областью видимости пользователя (регионы `users.regions`, УК `users.uks`).
* `groups[].area_delta` и `houses_delta` не согласованы с `area_in/area_out`
  (например, у региона есть приход и уход, а дельта равна нулю). Приложение считает
  дельту как «пришло − ушло», а `*_delta` использует только когда движения домов не было
  (изменение площади уже обслуживаемых домов — переобмер).
* `groups[].top_uks[]` содержит только `id`, `name` и дельты, без `area_in/area_out`.
  Разрез «Управляющие компании» в отчёте «Тренд» строится из этого списка.
* `series[]` за месяц возвращает одну корзину с недостоверными значениями
  (площадь порядка 1 м², количество домов больше всего фонда). Приложение рисует ряд как есть
  и показывает предупреждение, когда движение превышает весь фонд. **Требуется исправление
  на стороне кондуктора**; методы `.../houses` и `.../map` из спецификации пока не реализованы,
  поэтому детализация по домам и карта в приложении не включены.


### Что приложение присылает (с версии 1.0.7)

* Пресеты периода в интерфейсе: **Месяц**, **Квартал**, **Год**, **Произвольный период**.
* Для произвольного периода: `period=custom` и `from`/`to` в формате `Y-m-d`
  (даты выбираются во встроенном календаре), шаг графика подбирается по длине периода.
* Группировка переключается в самом отчёте: `group_by=region` или `group_by=uk`.
  При `group_by=uk` кондуктор должен отдавать группы с `kind: "uk"`, где `id` — идентификатор УК;
  бэкенд проверяет такие группы по списку доступных пользователю УК (`users.uks`).
